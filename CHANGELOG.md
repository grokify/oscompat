## [v0.9.0] - 2026-10-22

### Highlights

- Fixtures and golden files that compare equal on Windows, where git can check text files out with CRLF

### Added

- `testutil.ReadFileLF(t, path)` reads a text file and converts CRLF to LF
- `testutil.AssertGolden(t, path, got, update)` compares bytes with a golden file ignoring CRLF versus LF, and writes the file when `update` is set
- `fs.NormalizeLineEndingsBytes(b)` is `fs.NormalizeLineEndings` for bytes

### Documentation

- The testutil guide covers fixtures and golden files; the portable-tests guide recommends the helpers and `.gitattributes`; release notes for v0.9.0

## [v0.8.0] - 2026-10-22

### Highlights

- Path checks that give the same answer on every platform: `fs.ValidatePath` no longer depends on `filepath.IsAbs`, `fs.IsAbsAny` reports a path that is absolute or rooted anywhere, and `fs.ValidateSlashPath` checks paths that use forward slashes everywhere

### Added

- `fs.IsAbsAny(p)` reports whether a path is absolute or rooted on any platform: a leading `/` or `\`, a UNC path, or a drive letter, including the drive-relative `C:x` ([`5acd8e6`](https://github.com/grokify/oscompat/commit/5acd8e6))
- `fs.ValidateSlashPath(p)` checks a relative path that uses forward slashes on every platform, such as one inside a repository, an archive or a URL; it also refuses backslashes, colons, and empty or `.` elements, reported as the new `fs.ErrInvalidPath` ([`5baa804`](https://github.com/grokify/oscompat/commit/5baa804))

### Changed

- The path tests run every case on every platform instead of keeping absolute-path cases to the platform where each passed ([`e5e7164`](https://github.com/grokify/oscompat/commit/e5e7164))

### Fixed

- `fs.ValidatePath` gives the same answer on every platform: it rejected `/etc/passwd` only off Windows, and accepted `\etc\passwd` and `\\server\share` off Windows ([`5acd8e6`](https://github.com/grokify/oscompat/commit/5acd8e6))

### Documentation

- The fs guide explains which path check to use for a path on this machine, a path from elsewhere, and a forward-slash path; the portable-tests and getting-started guides, README and roadmap list the new functions; release notes for v0.8.0

## [v0.7.0] - 2026-10-12

### Highlights

- File locking, directory sync and permission checks, so modules stop keeping platform-specific files of their own; and a test that enforces that oscompat has no dependencies

### Added

- `fs.Lock(ctx, path)` takes an exclusive advisory lock between processes (`flock` on Unix, `LockFileEx` on Windows), waits until the context ends, and releases when the process exits; `fs.ErrLockUnsupported` on a platform with no locking
- `fs.SyncDir(dir)` flushes a directory so a rename is durable, and does nothing where the platform offers no way to
- `fs.PermissionsEnforced()`, `fs.IsPrivate`, `fs.CheckPrivate` (wrapping `fs.ErrNotPrivate`) and `fs.ChmodPrivate` for owner-only checks that are correct on Windows
- A test that fails on any dependency, `go.sum` or import outside the standard library and the module, and package documentation stating the policy

### Changed

- Portable-tests guide: use `fs.PermissionsEnforced()` for mode assertions, close handles in simulated-crash tests, and use `fs.Lock` and `fs.SyncDir`
- A MkDocs site with a guide for each package, and release notes for v0.7.0; the `paths` documentation now matches the directories the code returns for cache, runtime and macOS system configuration

## [v0.6.0] - 2026-10-08

### Highlights

- Process liveness, start time, and exec: detect a reused PID and hand the terminal to another program on Unix and Windows

### Added

- `process.Exists(pid)` reports whether a process is running; a process owned by another user counts as running, and non-positive PIDs are rejected because they address process groups on Unix ([`1814d6b`](https://github.com/grokify/oscompat/commit/1814d6b))
- `process.StartTime(pid)` returns when a process started (ps on Unix, process creation time on Windows) or `process.ErrNotFound`, so a stale record naming a reused PID can be detected ([`1814d6b`](https://github.com/grokify/oscompat/commit/1814d6b))
- `process.Exec(path, argv)` replaces the current process on Unix and runs the program as a child that exits with its status on Windows ([`1814d6b`](https://github.com/grokify/oscompat/commit/1814d6b))

## [v0.1.0] - 2025-01-17

### Highlights

- Initial release with cross-platform utilities for Go

### Added

- `id` package: Cross-platform unique identifier generation using `crypto/rand`
- `process` package: Cross-platform process management (detach, signal)
- `paths` package: XDG-compliant config/data/cache directory resolution
- `fs` package: Path validation, normalization, permissions, birthtime
- `tsync` package: Tolerant timestamp comparison for file sync
- `localnet` package: Cross-platform local IPC (Unix sockets / TCP)
